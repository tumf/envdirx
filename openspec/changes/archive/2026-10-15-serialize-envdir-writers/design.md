# Design

## Admission and lifetime

Add one `_writer_lock(directory)` context manager in `src/envdirx/__init__.py`. Resolve `directory` strictly to a real existing directory. Open its parent read-only using `O_DIRECTORY | O_NOFOLLOW` (Python FD is non-inheritable); use `fcntl.flock(fd, LOCK_EX | LOCK_NB)` and always close the FD in `finally`, even on failed acquisition. Do not unlink, chmod or create any filesystem path. Opening requires the parent to be readable/searchable; deny rather than falling back on failure. `BlockingIOError`/EAGAIN/EWOULDBLOCK from flock maps to `ValueError("envdir is busy: another envdirx writer holds the parent directory lock; retry after it finishes")`; other open/flock OSErrors retain main's existing sanitized exit-111 handler. Yield the resolved path so all accesses in this command use the admitted target. No lock file or PID/timeout lease is needed. Do not substitute lockf/F_SETLK: `_retire` opens/closes a second parent FD and POSIX record locks would be released by that close.

Route only `keygen`, `set`, `encrypt`, `decrypt`, `rekey` through this guard in `main`, after argument validation and existing-directory validation, before stdin reads and before entering private mutation helpers. Keep help/version, get, run and mkdir outside the guard. Holding through stdin is intentional: a competing set must fail before waiting for its input; interrupted input releases the lock with current exit behavior. Direct calls to private underscore functions are not a supported public mutation interface. One native `flock` controls the complete CLI mutation; no nested acquisition, global registry or broad refactor.

Parent-directory scope is deliberately coarser than per-envdir: all children of the same resolved parent contend. No blocking wait/retry is performed. This avoids persistent sidecars, XDG/HOME-dependent lock identities, key-store permission dependencies, hashing paths and unsafe stale-lock unlink. Add one short `ponytail:` comment explaining cooperative local parent scope and that finer granularity can be added when needed. Relative/canonical/symlink envdir and parent aliases resolve to the same parent inode. Do not lock the active envdir inode because native exchange replaces it. Parent rename/replacement by an uncooperative actor remains out of scope.

## Commit and termination

Preserve existing `_rekey` logic: preflight and verification in memory, private staging, native exchange, `_commit_state` inode-based cleanup decisions, old-key retention. Hold lock across every part including `_retire` and exception cleanup. No automatic swap-back after exchange. Before-commit exceptions retain original data; after-commit errors retain new active key/tree. SIGTERM and SIGKILL rely on OS FD closure, not handlers or PID expiry. Handled interruptions release via `finally`. Crash residues may remain and remain outside active DIR; next invocation can acquire the lock and operate on current DIR without adopting/removing them. Keep existing manual pointer-check cleanup guidance. Lock release is automatic recovery of admission, not automatic garbage collection or a power-loss guarantee.

## Verification design

Extend `tests/test_envdirx.py` with a dedicated WriterLockTest and test-local child scripts. No production pause/fault flags. A child patches the actual invoked `_exchange`, `_set`, `_keygen` or `_transform` boundary and calls `main` with synthetic args. Use a pipe/barrier acknowledgement *after* lock admission and immediately before the boundary, with bounded IPC waits. Never infer readiness from sleeps/file existence alone. Real OS processes and real host native exchange prove critical assertions; mocks are limited to pausing exact boundaries/error injection.

Required matrix:
- rekey paused before final exchange; second rekey (direct and aliases), set new/update (plain and encrypted), encrypt/decrypt --all and keygen all refuse busy, no stdout, unchanged complete fixture snapshot including external key/store. Resume then retry set/update, read exact expected values, including encrypted write under new pubkey.
- rekey paused immediately after final exchange / before cleanup: second writer still refuses, proving the stable lock survived exchange. Resume and prove lock release. Also pause before `_retire` return or inject its exception to prove cleanup/failure scope.
- writer paused inside each of `_set`, `_keygen`, `_transform`: competing rekey refuses; successful writer followed by rekey preserves its committed result. Include long set input cancellation using a controlled stdin barrier and current 130/no-write contract.
- killed/reaped child for SIGTERM and SIGKILL before/after the actual exchange: matching active pointer/ciphertexts/get/run; old key unchanged; next set and rekey succeed without manual residue deletion. New after-commit key is never deleted. Preserve/extend existing error-injection tests and show guard release after validation failure, pre-exchange I/O failure, post-exchange cleanup failure and KeyboardInterrupt.
- same parent different envdir contention is intentional, different parent can write; read-only commands work while another writer is paused (not across the swap itself), no leaked lock artifact, non-inheritable FD.
- parent open/flock error has 111/no side effects; no unlocked fallback. At least one causal control disabling actual flock in the isolated child must make a contender test fail rather than pass with a missing barrier.

Use fixture HOME and unset or synthetic absolute XDG_DATA_HOME; never production keys. Assert exact error category/status and successful barrier consumption; timeouts/unknown child state are failures. Keep existing full 96+ tests; do not weaken snapshots or exclude safety tests to pass. If lock artifacts unexpectedly appear, fix implementation rather than excluding them from snapshots. Host tests can run real POSIX locks; Linux syscall ABI tests alone do not claim Linux runtime acceptance.
